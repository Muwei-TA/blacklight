# 黑光文学社：小程序迁移为网站

## 目标与依据
用户要求阅读前后端的 `codex/admin-governance-20261003` 分支，规划并实现浏览器版本，已选择账号密码登录。参考前端提交 `90e84df`、后端提交 `16ce74d`。目标是手机与电脑均能使用现有社团业务，并脱离小程序登录与发布渠道。原权限和数据库是迁移依据，历史 README 的 CloudBase / 单社团描述已落后于这两个分支的实际代码。

## 方案比较与选择
1. 推荐：在 blacklight 中增加无构建依赖的模块化成员网页，由现有 Node 服务提供同域静态文件和 Cookie API。复用 PostgreSQL、领域 action、管理台、签名媒体与 worker，部署单元少。
2. 单独的 Vue / React 网站：生态丰富，但要增加构建产物、跨域部署及双仓库发布协调，当前规模没有必要。
3. 直接转译小程序或 H5 容器：布局受原生组件约束，微信身份和 API 依赖仍需改造，收益有限。

## 架构与安全
`web/` 为成员端，`admin-web/` 为治理端，`server/web-auth.js` 管账号密码和网站会话，`server/web-http.js` 管同域 API 与静态文件。`/v1/web/action` 将服务端验证后的身份传入原 router。保留历史 wxOpenIdRef 作为内部身份引用；新网站身份为服务端随机 `web:<uuid>`，客户端不能指定，也不当作真实微信 openid 调内容安全。

账号为 3–32 位 ASCII 字母数字下划线，规范为小写。密码为 10–128 字符，使用随机盐 scrypt；不保存明文。Cookie 使用 HttpOnly、SameSite=Lax、Path=/，生产 Secure 和 __Host- 前缀。会话仅存 SHA-256 摘要，7 天绝对期限、24 小时闲置期限。来源固定为 PUBLIC_API_BASE_URL 的 origin，写请求核验 Origin 与 CSRF；注册、登录通过 PostgreSQL 原子窗口按账号和来源限频。客户端不能指定角色，注册账号默认无社团资格。

每次 action 继续实时查成员资格，匿名 DTO 不包含作者 ID，私密内容不进入聚合列表，媒体仍经签名 URL 校验。网站会话可进入现有管理台，但仍按原角色权限过滤；换届和移除不能依赖客户端缓存。

## 功能与交互
暖白纸张、森林绿、衬线标题，电脑侧栏、手机底部导航。社团选择 → 邀请码入社 → 树洞信息流/搜索 → 内容详情/回应/共鸣/收藏；支持话题和板块列表、详情、创建，文集目录/投稿授权/撤回，发布署名或匿名、社内/公开（能力允许时）/仅自己，个人内容状态列表、退回重提、删除/缩小范围/申诉、站内消息、昵称及密码修改、注销申请、签到等级、换届和恢复确认。所有列表支持服务器游标分页，页面切换防止旧请求写入新社团。

不在浏览器持久保存正文草稿、用户作品和身份令牌；同一次发布网络重试复用幂等键。正文按纯文本显示，不能执行 HTML。错误、空态、处理中、待审状态必须有明确文案。

## 微信能力迁移
`REVIEW_PROVIDER=manual` 可在没有微信配置时运行，文本立即进入人工审核，绝不自动通过。此模式网站不开放新图片/视频上传，仍可阅读历史已审核图片；现有图片链路可在继续配置微信图片检查时使用。通用第三方图片审核服务和视频转码作为后续扩展。人工值守是网站发布闭环的一部分。密码遗忘、旧账号绑定由服务端运维工具核实身份后设置，不能按昵称自动合并。

## 数据、运行与验收
新增独立迁移，不重写旧用户或内容。运维 CLI 通过用户 ID 给已有用户配置网站凭据；不在公开注册接口开放绑定。提供网站 Compose、反向代理说明与本地启动指引，不访问或修改现有生产数据库，不自动公网部署。

验收覆盖密码散列/错误密码、注册并发/冲突、限频、Cookie/Origin/CSRF、退出/过期/账号删除、网站 action 不信客户端身份、管理台登录桥接、真实 PostgreSQL 上注册/入社/匿名和私密发布/审核/回应/收藏/社团切换隔离。桌面和手机浏览器检查导航、发布和错误态。

## 上线边界
网站备案取决于部署地区和运营方式；这次不承诺免备案。保留原项目 publicScope、视频和导出能力开关，未实现的数据导出文件生成不在本次迁移中伪装完成。
