# 01｜技术决策记录与边界

## 1.1 决策：使用微信云开发 CloudBase

**决策日期**：2026-09-22 ｜ **决策人**：项目方 ｜ **状态**：已确认

前端工程书 `02-architecture.md` §2.7 要求"CloudBase 与自建 API 二选一并形成决策记录，
不要同时搭两套"。本项目选择 **CloudBase**。

| 维度 | CloudBase（已选） | 自建 API 服务（未选） |
|---|---|---|
| 身份 | `cloud.getWXContext()` 直接拿到可信 openid，无需自建登录换票 | 需实现 `code2session` + 会话签发与续期 |
| 运维 | 无服务器运维，自动扩缩 | 需要机器、域名、证书、部署流水线 |
| 媒体 | 云存储 + 云函数天然打通，私有桶权限简单 | 需自建对象存储与鉴权代理 |
| 内容安全 | 云调用可直接调 `security.*` 接口，免 access_token 管理 | 需自行维护 access_token 与调用 |
| 单社团规模 | 30–60 人试点用量极小，成本可控 | 固定成本偏高 |
| 代价 | 绑定腾讯生态；数据库权限粒度粗；调试不如本地服务方便 | 更灵活但工作量大得多 |

**关键取舍**：CloudBase 的数据库权限粒度做不到"社内成员且已发布且非匿名映射"这种条件，
因此本项目**所有集合设为「仅管理端可读写」，前端禁止 `wx.cloud.database()` 直连**，
所有读写必须经过 `api` 云函数。这是用架构约束换取权限可控性，也是 `05` 全部规则得以成立的前提。

## 1.2 架构形态：单部署单元 + 模块化

前端工程书建议"一个后端部署单元，按业务模块分层；不先拆微服务"。落地为三个云函数：

| 云函数 | 职责 | 触发方式 |
|---|---|---|
| `api` | 所有面向小程序的读写请求 | 小程序 `callFunction` |
| `worker` | 审核、媒体处理、共鸣聚合、清理、注销执行 | 定时触发器（每分钟） |
| `review-callback` | 接收内容安全异步检查结果 | 消息推送 / HTTP |

三者共享 `shared/`（权限、校验、DTO、数据访问）。**权限规则只有一份实现**，
客户端请求与后台任务共用，不各自复制判断。

## 1.3 为什么不用 Node 版 ORM / 框架

云函数冷启动对包体积敏感，且本项目数据模型简单（22 个集合、无复杂 join）。
直接用 `wx-server-sdk` 的 database API + 一层薄封装（`shared/db.js`）即可。
**云函数生产依赖只有 `wx-server-sdk`**，新增依赖需在任务板申请并说明冷启动影响。

## 1.4 服务范围（与前端 P0 对齐）

| 模块 | 后端职责 |
|---|---|
| 加入与成员资格 | openid → 内部用户、邀请码校验与限频、申请与人工批准、退社权限回收 |
| 内容发布 | 校验、幂等、附件绑定、审核任务创建、状态机流转 |
| 范围与身份 | 可见范围过滤、匿名别名派生与映射隔离、能力开关 |
| 互动与找回 | 共鸣/收藏幂等、评论审核、通知生成、权限内搜索 |
| 话题 | 提交待审、同名引导、归档、参与计数 |
| 板块 | 独立的帖子分流对象；成员申请待审，管理员创建后直接生效 |
| 文集 | 授权记录、范围交集校验、人工收录、撤回联动 |
| 管理与安全 | 独立审核队列、版本锁、处理理由、审计日志、受控匿名查询 |
| 个人空间 | 各状态列表、失效收藏占位、导出、注销与保留策略 |

## 1.5 明确不做（首版）

- 私信/IM、WebSocket 长连接（前端也已移除聊天链路）
- 热度排行、推荐算法、关注关系
- 多租户（保留 `clubId` 字段便于边界测试，但不建设租户隔离）
- 全文检索引擎（用数据库正则匹配，首版规模够用；正则已转义防注入）
- 富文本 HTML 存储（正文为纯文本 + 换行，段落由服务端按空行切分）
- 成员移除/禁言/角色调整的管理接口（首版运营在控制台操作，见 `07`）

## 1.6 能力开关（服务端唯一来源）

存于 `hg_club_config` 文档，由 `shared/session.js` 读取，**读取失败按全部关闭处理**。

```js
capabilities: {
  publicScope: false,  // 公开可见范围。G0 未完成前必须 false
  video:       false,  // 视频链路。转码未接入 + 审核未实测，必须 false
  anthology:   true,   // 文集投稿
  export:      false,  // 数据导出。实际文件生成未实现
}
```

前端只读这些字段，**不得本地硬编码**。后端在 `policies.canUsePublicVisibility` /
`canUploadVideo` 中强制校验 —— 前端隐藏按钮不构成保护。

## 1.9 术语与代码标识对照

沿用前端 `docs/01` 1.8 的术语表。后端补充：

| 概念 | 代码标识 | 说明 |
|---|---|---|

## 1.10 板块与话题是两个独立对象

板块用于把帖子分流到不同栏目，话题用于标注帖子讨论内容。两者使用独立数据表、接口、审核队列和 DTO；新板块写入 `hg_boards`，不得写入 `hg_topics`。

帖子可同时带一个可选 `boardId` 和一个可选 `topicId`，二者互不排斥，也不相互推导。仅自己可见的帖子不得关联社内板块；服务端校验板块状态与成员资格，板块必须为 `active` 才能投稿。
