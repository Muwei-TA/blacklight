## 1. 目标与边界

- 让社内成员看见长期参与的进度，鼓励稳定互动，而非以等级衡量内容质量、可信度或社团身份。
- 经验值只来自每天签到、给已发布内容点赞、发表并通过审核的回应（含回复）。首版不设连续签到惩罚、排行榜、付费加速或等级特权。
- 等级不参与发帖权限、审核决策、内容排序和管理员角色判断。退出或失去成员资格后停止新增经验；账号删除沿用现有删除流程处理等级记录。
- 首版名牌只在“我的”页面展示。公开署名页/评论旁展示名牌列为后续可选项，须先验证不会借等级变化推断匿名互动。

## 2. 获取规则（建议值）

| 行为 | 经验 | 每日上限 | 生效时点与去重 |
| --- | ---: | ---: | --- |
| 签到 | +5 | 1 次，5 XP | 有效成员主动点击签到；同一账号同一自然日只记一次 |
| 共鸣（点赞）帖子或回应 | +1 | 5 个不同目标，5 XP | 对已发布且有权访问的目标从未点赞变成点赞；同一目标终身最多奖励一次，取消后重赞不再奖励 |
| 发表回应或回复 | +3 | 3 个不同帖子，9 XP | 回应审核通过且仍可见时入账；同一帖子同一获奖日仅首条通过审核的回应奖励 |

单日最多 **19 XP**。自然日按服务端的 `Asia/Shanghai` 日历日计算，00:00 重置；评论以审核通过日作为获奖日。没有签到补签或连续天数加成；每日上限统计已发放次数，撤销经验不返还当天名额。给自己的帖子或回应点赞不计经验，但不改变原有点赞行为。私密/未发布内容不计点赞经验。匿名回应通过审核也能给作者记经验，但经验事件、匿名目标与账号的关联仅服务端可见，任何公开 DTO 不携带这类线索。

撤销规则已按本稿实现：驳回不发经验；评论从 `published` 因违规改为 `hidden` / `rejected` 时写入一次反向流水并重新计算等级。用户自行删除评论时保留参与经验；账号注销最终进入 `deleted` 状态后，清除该账号的汇总和 XP 流水。被撤销的奖励不返还当日名额。取消点赞不扣经验，奖励绑定首次有效参与。

## 3. 等级与名牌

累计经验达到门槛即升级，门槛固定、无赛季清零。L8 后继续累计经验但保持 L8；后续扩展等级需做规则版本说明。下表门槛按每天拿满 19 XP 计算只是理论最快速度，不代表用户目标。

| 等级 | 累计 XP 起点 | 名牌文案 | 文字/边框 | 浅色底 | 理论最快达到 |
| --- | ---: | --- | --- | --- | ---: |
| L1 | 0 | 微光 | `#4C5B4A` | `#F1F2E8` | 入社即有 |
| L2 | 40 | 新芽 | `#315948` | `#E9EEE4` | 3 天 |
| L3 | 120 | 青枝 | `#2C625C` | `#E2EFEB` | 7 天 |
| L4 | 280 | 向光 | `#315A78` | `#E7F0F5` | 15 天 |
| L5 | 520 | 成荫 | `#664B73` | `#F0EAF2` | 28 天 |
| L6 | 860 | 星枝 | `#805130` | `#F6EDE3` | 46 天 |
| L7 | 1320 | 林海 | `#82465C` | `#F8EBEF` | 70 天 |
| L8 | 2000 | 长明 | `#714F23` | `#F7F0DF` | 106 天 |

名牌统一为 `Lv.3 青枝` 这种“等级号 + 名称”结构，圆角矩形、浅底、同色细边和深色文字。API 的 `title` 只返回名称，前端组合等级号。配色延续现有暖纸白、墨绿和陶土色系；上表文字/背景对比度均高于 5.7:1。不能仅靠颜色区分等级；缩小字体或系统高对比度设置下仍需读得清。避免皇冠、勋章或“认证”等容易被误认成官方权力的图形。实现时把色值集中到前端设计令牌，不在页面散写裸色值。初版用现有字体和 CSS 绘制，不增加外部图片资源。

## 4. 页面草图

“我的”成员卡片昵称下放名牌与进度：

```text
南枝  [Lv.3 青枝]
累计 135 XP     距 Lv.4 还差 145 XP
[●─────────────]  本级进度 15 / 160 XP

[ 今日签到  +5 XP ]   今日已签到后显示「明天再来」
今日经验  8 / 19       查看等级规则 ›
```

进度条实际按本级区间计算，例如 L3 在 120–280 XP 区间，135 XP 时进度为 `15 / 160`，不能把 `135 / 280` 直接画成区间进度。签到成功只出现一次轻提示；网络失败保留可重试按钮，服务端返回当日已签则同步为已签到。规则页解释获奖时点、每日上限、匿名保护与等级不代表身份或可信度。非成员不展示经验和签到入口；读取失败不覆盖上一次已确认的当前账号数据，切换账号时清空旧数据。

## 5. 实现轮廓

- **数据**：CloudBase PG 新增 `hg_user_xp_events` 私有流水表与 `hg_user_xp_accounts` 汇总表，追加 migration 不改已应用迁移。流水带用户、事件类型、来源 ID、业务日、XP、规则版本、反向事件和唯一幂等键；约束和索引执行签到、点赞、回应的每日额度。公开接口不返回来源 ID，也不回填 migration 前的点赞和已发布回应。
- **原子性**：签到由服务端事务核验成员资格、当日唯一性、计数和总 XP。点赞奖励只随 `hg_reactions` 实际 INSERT；评论奖励随 `hg_comments` 从待审转为 `published`，覆盖自动审核和人工审核最终状态。`published` 后因违规变为 `hidden` / `rejected` 时同事务反向记账。审核触发器遇成员行并发更新时用 `NOWAIT` 失败关闭，整笔审核回滚后由 worker 退避重试，人工审核返回可重试冲突。
- **接口**：已实现 `me/levels` 返回本人等级、累计 XP、本级/下级门槛、进度和今日额度；`me/check-in` 返回最新快照及 `awardedXp`。身份只取服务端会话，不接受客户端指定 `userId`、经验数或业务日。L8 `nextLevelXp: null`、`progressTargetXp: 0`，`progressXp` 只表示超过 2000 XP 的累计量。
- **前端**：在 `pages/my` 的成员态加入等级卡与签到按钮；复用现有 request、会话状态与账号作用域缓存规则。页面进度和等级由服务端快照计算，客户端只负责展示。首版不改帖子卡、评论 DTO 与公开社员主页。
- **观测与修正**：XP 流水为事实来源，汇总在同一事务更新；本版没有管理台手工覆盖入口。后续如需修复，应实现只对当前管理员开放、写审计记录的对账操作，禁止直接改汇总而不留流水。

## 6. 验收清单

1. 同日重复签到、多端并发签到、跨零点签到只有符合规则的流水和经验；匿名或被移除成员不能签到。
2. 点赞重试、取消/重赞、自己给自己点赞、不同帖子和回应的上限均正确；原有点赞数不受影响。
3. 待审/驳回评论不加分；自动或人工通过只加一次；违规撤下有反向流水；自行删除不重复获得经验。
4. 等级门槛、进度条、每日 19 XP 上限计算正确；切换账号、网络错误、匿名帖/匿名回应不会泄露等级或用户关联。
5. 前端 `npm run check`、`npm run lint`、`npm test`，后端对应检查、隔离 PG 事务/并发测试通过；微信开发者工具页面交互另验。云端、体验版、真机和正式发布分别验收，不由本草稿的静态检查代替。

## 7. 待定产品选择

- 名牌是否以后开放到**署名**内容旁：建议先以隐私评估与用户主动开启为前提；匿名内容始终不展示。
- 上线后的实际参与分布若明显偏离预期，可调整新等级门槛或新增等级，但已经获得的经验不回收，调整需版本化并向用户说明。
